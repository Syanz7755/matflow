# MatFlow 面试准备：实现、证据与边界

日期：2026-10-19。针对当前本地工作区；未经提交、推送的改动不能声称已在公开仓库交付。以下介绍描述系统设计，不替代个人贡献记录；面试时只认领自己实际完成、能解释并复现的工作。

## 90 秒介绍

MatFlow 是面向材料研究的工作流后端。我关注的问题是：对话模型能提出分析建议，但研究者还需要检查每一步的数据、方法、参数和结果，才能重复运行或修改实验分析。

系统把研究请求交给模型分解，再从输入类型兼容的注册工具中选择工具，形成可校验的 DAG。后端管理工作区状态、图补丁、执行、人工审核和持久化；科学方法放在独立的 Domain Package 中，前端和 MCP 桥通过 HTTP 使用同一套后端。

目前最适合演示的是平台机制和一条 QE 历史输出回放：四个节点完成结构、输入生成、输出回放和解析，能离线重跑并检查来源哈希。我会明确区分固定回放与模型规划，也不会把图校验通过等同于科学结论正确。当前限制包括工具覆盖较少、在线规划慢且有波动、单用户本地存储，以及尚未完成的 EBrick 全链路分析。

## 演示顺序

1. 先讲请求、Tool、Node、GraphPatch、Artifact 的关系，见 [术语](../CONTEXT.md)。
2. 用 [A1 的 3 分钟脚本](../examples/cases/A1-qe-mgo/README.md) 运行 `uv run matflow demo qe-mgo --output <新目录>`。无需密钥、HPC 或 QE 安装。
3. 展示 `summary.json`、四节点图和历史回放标记，重复指定同一个目录，展示拒绝覆盖。
4. 展示 [评测方法](ROUTING_EVALUATION.md) 和 [本次复核说明](evaluation/README.md)。模型规划是另一条需要在线服务的路径，不把固定演示说成自然语言自动规划。
5. 若前端可用，在单独的新存档中打开演示；不要临场改真实研究存档。

## 核心追问

| 追问 | 可使用的回答 | 代码和验证入口 |
|---|---|---|
| 为什么不直接用带 Python 插件的 harness？ | harness 擅长对话和临时工具调用。MatFlow 增加持久的类型化依赖图、版本校验、显式审核和注册工具执行，适合需要重复运行和检查中间结果的任务。代价是灵活性较低，需要先有工具；尚未完成 DSH 对照实验，不能宣称优于 harness。 | [WorkspaceRuntime](../backend/workspace_runtime.py)、[图校验](../backend/validator.py)、[执行器](../backend/executors.py) |
| 图和类型系统解决什么？ | 在执行前检查端口兼容、缺失依赖和环等结构错误，图补丁还检查版本冲突。类型名称不能证明量纲、实验协议或科学方法正确，这些需要领域校验和外部验证。 | [contracts](../backend/contracts.py)、[validator](../backend/validator.py)、[类型测试](../tests/test_data_types.py) |
| 路由是不是关键词匹配？中文怎么办？ | 候选只按工具状态、可选择性和输入类型过滤。工具语义选择来自 Jev 或 LLM；模型不可用时交给人。中文原文能进入模型路径；中英文候选一致的离线测试不代表两种语言的模型准确率相同。 | [routing](../backend/routing.py)、[planner](../backend/planner.py)、[中文测试](../tests/test_cjk_prompts.py) |
| 模型输出错误怎么办？ | 分解和选择结果受结构约束，选择不能越过候选集。缺工具、缺参数、低置信度或校验失败会形成缺口或确认状态，只有符合应用条件的补丁才能应用。审核机制也可能依赖模型正确识别风险，并非能抵御所有提示注入。 | [planner](../backend/planner.py)、[路由行为测试](../tests/test_jev_decision_behavior.py)、[规划测试](../tests/test_workflow_planner.py) |
| 工具能自动生成并发布吗？ | 已实现受限的声明式 Recipe 构造、评估、修复和审核流程；不是任意 Python 代码的安全沙箱。Domain Package 的结构校验不等于插件可信或已签名。 | [Recipe 引擎](../backend/analysis_recipes.py)、[生命周期测试](../tests/test_tool_recipe_lifecycle.py)、[领域包契约](DOMAIN_PACKAGES.md) |
| 质量门和人工审核有什么区别？ | 条件门根据结构化报告决定继续或停止；人工审核由人决定继续、修改或停止。平台能提供机制，但每种领域的门限和适用协议还要由科学证据确定。 | [控制节点测试](../tests/test_generic_control_nodes.py)、[执行器](../backend/executors.py) |
| QE 演示是不是实际计算？ | 不是。现有演示生成输入并解析打包的历史 stdout；没有运行 pw.x、验证赝势或向 Slurm 提交。执行器接口是扩展点，不能据此声称已交付 HPC 调度。 | [显式演示](../backend/demo.py)、[QE 回放包](../backend/domain_packages/qe_demo.py)、[演示限制](../examples/cases/A1-qe-mgo/LIMITATIONS.md) |
| 如何评价模型与系统可靠性？ | 分开测试确定性壳层、在线规划和执行结果。离线测试检查契约和状态，在线评测记录选择、缺口、确认、失败及延迟；科学正确性需要另有标注、负对照和真实数据验证。旧 18 条评测混有大量超时，不用于模型排名。 | [评测方法](ROUTING_EVALUATION.md)、[评测回归](../tests/test_routing_online_eval.py)、[本次复核](evaluation/README.md) |

## 可以展示与仍需补齐

| 状态 | 内容 |
|---|---|
| 已有实现，可检查证据 | 类型和图补丁校验；工作区持久化；DAG 执行、控制节点和审核；Domain Package；受限 Recipe 生命周期；显式 QE 离线回放；中文节点和上传处理 |
| 已有实现，可靠性仍需量化 | LLM 分解、逐步路由、端口和参数绑定；复杂中文及长请求规划；Jev 服务与 LLM 回退 |
| 本轮没有完成 | 旗舰 EBrick EIS 的 Cp/G→Z、温度映射、KK/ECM/DRT、σ(T) 全链路；真实数据脱敏审核；DSH 对照；前端 e2e 收尾和截图；公开发布 |
| 当前产品边界 | 单用户、本地文件存储、有限领域工具；没有公开网络认证、多租户隔离、任意生成代码安全执行或已交付的远程 HPC 调度 |

## 面试前自查

- 能独立解释一个请求如何经过分解、候选过滤、选择、校验与执行；准备一个失败分支。
- 能说出固定 QE 案例的来源、单位、哈希和回放边界；不把 SCF 收敛称为材料机理验证。
- 准备展示自己实际参与的提交或设计改动，不用测试数量替代贡献说明。
- 现场使用新目录；确认公开链接对应的版本。尚未推送时，说明演示来自本地工作区。
